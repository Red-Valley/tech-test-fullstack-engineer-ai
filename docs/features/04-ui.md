# Feature: UI

A mobile-first Next.js App Router interface with a game catalog dashboard and an embedded AI chat surface.

---

## Application Structure

```
app/
├── layout.tsx          ← Root layout: <html>, font, global styles
├── globals.css         ← Tailwind base + dialog UA override
└── page.tsx            ← Server Component: fetches games from DB, renders shell

components/
├── games/
│   ├── games-view.tsx      ← "use client": dialog state, router.refresh()
│   ├── game-card.tsx       ← Server-compatible card (article + dl metrics)
│   ├── game-form-dialog.tsx ← Create / Edit form dialog
│   └── delete-dialog.tsx   ← Confirm-delete dialog
└── chat/
    ├── chat-dock.tsx        ← FAB button that toggles the drawer
    ├── chat-drawer.tsx      ← <dialog> sliding panel (right-anchored on desktop)
    ├── chat-scaffold.tsx    ← "use client": useChat, message render, composer
    └── answer-card.tsx      ← Renders CatalogAnswer (6 kinds of structured cards)
```

---

## Data Flow

`app/page.tsx` is a **Server Component**. It calls `getGamesRepository().list()` directly (no HTTP round-trip) and passes the resulting `Game[]` to `<GamesView>`. After any mutation (create, edit, delete), the client calls `router.refresh()` which triggers a server re-render and passes the updated list down — no client-side state for the game list.

```
Server                          Client
──────                          ──────
page.tsx                        GamesView (state: which dialog is open)
  └─ getGamesRepository()         ├─ GameCard × N (displays game)
  └─ <GamesView games={...} />    ├─ GameFormDialog (create / edit)
                                  └─ DeleteDialog (confirm delete)
                                  
                                ChatDock (open/close toggle)
                                  └─ ChatDrawer (<dialog> modal)
                                       └─ ChatScaffold (useChat, stream)
                                            └─ AnswerCard (structured output)
```

## Game Catalog

### `GameCard`
Renders a single game as an `<article>` with a `<dl>` for the three metrics (Revenue, Downloads, Rating). Uses `formatCurrency`, `formatCompact`, and `formatRating` from [`lib/games/format.ts`](../../lib/games/format.ts) — all backed by `Intl.NumberFormat` for locale-correctness.

Edit and Delete are `<button>` elements that trigger state changes in the parent `GamesView`.

### `GamesView`
Manages a `DialogState` discriminated union (`idle | create | edit | delete`). Renders the appropriate dialog based on state, then calls `onSuccess → setDialog("idle") + router.refresh()` on completion.

### `GameFormDialog`
- Uses React controlled form with a `FormStrings` state type (all fields as strings) to avoid uncontrolled/controlled input issues.
- Converts strings to numbers before Zod validation (`Number(form.monthly_revenue_usd)` etc.).
- Runs `gameInputSchema.safeParse` client-side before the fetch — field errors display inline under each input.
- Server validation errors from the API (400 response) are also reflected in `fieldErrors` state.
- Mode `"create"` → `POST /api/games`; mode `"edit"` → `PUT /api/games/:id`.

### `DeleteDialog`
Minimal confirmation dialog. On confirm: `DELETE /api/games/:id` → `onSuccess()`.

## Dialog Pattern

Both game dialogs and the chat drawer use the **native `<dialog>` element** with `showModal()` (called in `useEffect` on mount). This gives:
- Native browser backdrop via `::backdrop` pseudo-element — styled with `backdrop:bg-black/40`.
- ESC key closes the dialog natively (intercepted via `onCancel` to call the `onClose` prop instead of letting the browser manage open/closed state).
- Backdrop click closes via `onClick` on the `<dialog>` element checking `e.target === e.currentTarget`.

**Mobile layout:** bottom-sheet (`inset-x-0 top-auto bottom-0`). **Desktop layout:** centered modal (`sm:inset-0 sm:m-auto sm:max-w-*`).

The `globals.css` removes the UA's default `max-height` and `max-width` limits on `<dialog>` so Tailwind classes take full control.

## Chat Surface

### `ChatDock`
A fixed FAB (`position: fixed`, bottom-right) with a chat icon. Clicking it toggles `open` state which is passed to `<ChatDrawer>`.

### `ChatDrawer`
A `<dialog>` that slides in from the right on desktop (`sm:w-96 sm:right-0 sm:inset-y-0`) and goes fullscreen on mobile (`inset-0 w-full h-dvh`). The `bg-transparent` class removes the UA's white background, letting the `::backdrop` show through correctly. The inner `<div>` provides the white panel with `rounded-l-2xl` on desktop.

### `ChatScaffold`
Drives the chat UI with `useChat` from `@ai-sdk/react`:
- **Message log**: `role="log" aria-live="polite"` for screen reader support.
- **Composer**: `<textarea>` with `sr-only` label, Enter-to-send, auto-disabled during stream.
- **Part rendering**: see [Feature 03 — AI Chat](03-ai-chat.md) for the full rendering table.
- **Auto-scroll**: `useEffect` watching `messages` scrolls the log div to the bottom on each update.

### `AnswerCard`
See [Feature 03 — AI Chat](03-ai-chat.md) — Answer Card section.

## Styling Conventions

- **Tailwind v4** with PostCSS. No `tailwind.config.js` — configuration is in CSS via `@import "tailwindcss"`.
- **Mobile-first**: all base classes target ~360px; `sm:` (640px+) enhances layout.
- **Color palette**: sky-600 for primary actions, neutral-* for surfaces and text, red-600 for destructive actions.
- **Focus states**: `focus-visible:outline-2 focus-visible:outline-offset-2 focus-visible:outline-sky-600` on all interactive elements.
- **Tap targets**: all buttons use `min-h-11` (44px) to meet WCAG touch target requirements.
